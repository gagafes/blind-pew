# Blind Pew и похожие проекты

Проверено 4 ноября 2026 года по исходникам и документации указанных проектов.
Это сравнение назначения и архитектуры, а не сравнительный тест скорости,
надёжности или доказательство юридической уникальности.

## Возможности и область применения

| Проект | Основная задача | Отличие от Blind Pew | Лицензия проверенного компонента |
|---|---|---|---|
| **Blind Pew** | Транслитерация в Linux через IBus: 7 языков, 8 профилей, 16 сочетаний с QWERTY/QWERTZ | Собственное окно настройки, F12 и колесо над индикатором для пары «транслит ↔ обычный источник», предпросмотр и CLI; без словаря обучения | MIT для оригинальной реализации; происхождение внешних таблиц описано отдельно |
| **IBus m17n** | Подключение методов ввода m17n к IBus | Более широкий каталог языков/методов через m17n-db; использует инфраструктуру IBus и движок m17n вместо собственного преобразователя Blind Pew | GPL-2.0-or-later для адаптера; данные и ресурсы имеют собственные уведомления |
| **IBus Table / Translit** | Табличный ввод, в том числе русская транслитерация | Прямой аналог базовой функции; таблица Translit работает в общем движке IBus Table. Она не равна всем восьми профилям Blind Pew | Именно `tables/translit.txt`: LGPL-2.1-or-later; весь сборник содержит разные лицензии |
| **Fcitx5 m17n** | Методы m17n в экосистеме Fcitx5 | Подходящий аналог для пользователей Fcitx5; Blind Pew сейчас является движком IBus и не предоставляет адаптер Fcitx5 | LGPL-2.1-or-later для адаптера |
| **IBus Typing Booster** | Многоязычный ввод, подсказки, исправление и обучение | Использует m17n, словари и пользовательскую базу; существенно шире по функциям. Blind Pew выполняет предсказуемое преобразование без накопления истории набора | GPL-3.0-or-later; отдельные дополнительные компоненты — Apache-2.0 |
| **Translit, Eugene Gershnik** | Системная транслитерация на macOS | Близок по пользовательской задаче: русский, украинский, белорусский и иврит, выбор схем, включая Translit.ru; использует macOS InputMethodKit, а не Linux/IBus | GPL-3.0-or-later |

Для русского транслита без отдельного окна управления уже подходят существующие
IBus/m17n или IBus Table. Для подсказок и обучения Typing Booster решает более
широкую задачу. Blind Pew имеет смысл как небольшой законченный инструмент для
пользователя Debian/Ubuntu, которому нужны несколько конкретных схем,
QWERTY/QWERTZ и понятное включение/выключение через F12 и индикатор.

Сама идея транслитерации и схемы вроде `sh → ш` не уникальны. Отличие Blind Pew —
сочетание выбранных профилей, собственного небольшого преобразователя,
управления парой источников, интерфейса и упаковки для GNOME/XFCE.

## Сравнение реализации

- **Blind Pew:** Python-преобразователь хранит короткий суффикс уже отображённого
  текста, применяет правила к этому суффиксу и новому символу; адаптер IBus
  публикует preedit и фиксирует готовый префикс. Не читает окружающий текст.
- **IBus m17n / Fcitx5 m17n:** C/C++-адаптеры передают ввод библиотеке m17n.
  Это иная структура движка и иной формат данных.
- **IBus Table / Translit:** декларативная таблица последовательностей и
  результатов плюс общий табличный движок. У неё собственные параметры
  автоматической фиксации, кандидатов и клавиш.
- **Typing Booster:** большой Python-движок IBus, преобразование m17n,
  словари/кандидаты и обучение; совпадение классов IBus и названий методов
  обусловлено общим API и само по себе не означает заимствование.
- **Translit для macOS:** C++/Objective-C++ с prefix mapper и отдельными
  буферами исходного префикса/преобразованного результата; не является исходной
  копией Python-преобразователя Blind Pew.

Сравнение Git blob SHA исходного импортированного Blind Pew со всеми пятью
репозиториями не выявило полностью одинаковых файлов. Проверены также основные
адаптеры/преобразователи и их лицензии. Это ограниченный поиск: он не обнаруживает
все возможные переработки, перевод кода на другой язык или совпадения с
непроверенными репозиториями. Процент «уникальности» не вычислялся.

## Что стоит улучшать в Blind Pew дальше

1. Расширять подтверждённую совместимость: реальные Qt/Electron-приложения,
   Flatpak/Snap, клавиатуры и пользовательские GNOME/Wayland-сеансы.
2. Сделать сочетание переключения настраиваемым: фиксированный F12 может
   конфликтовать с привычками пользователя и приложениями.
3. Рассмотреть явно лицензируемые пользовательские схемы и импорт/экспорт
   профилей с сохранением происхождения данных.
4. Добавлять интеграцию Fcitx5 только при реальной потребности пользователей;
   существующий адаптер m17n уже закрывает многие сценарии этой экосистемы.
5. Подтверждать преимущество по задержке и памяти измерениями на одинаковых
   системах; компактный исходный код сам по себе не доказывает быстродействие.
